# Security audit: serverless-dns

**Historical baseline.** For the subsequent fixes, local verification, and remaining operator gates, see the [security rollout](../rollout.md).

**18 November 2026 · Release recommendation: hold public deployment.** A DNS client and an upstream resolver are different trust boundaries. The current cache can store a client's packet as an upstream answer. Independently, the pinned DNS decoder has an unbounded synchronous path before authentication. Fix both before exposing even a resolver with logging turned off. Do not rely on `ACCESS_KEYS` to contain either issue.

This is a review of the **working tree**, including local changes, locks and tests, on `arena/9bfe266d-serverless-dns`, based on `ff7aa7339efeafa0887b4291ff29ad97259ac45c`. Paths and line numbers below are relative to the repository root unless linked to a pinned dependency. Findings describe code and prerequisites, **not evidence of a compromise or of a particular live deployment**. No application, workflow or lockfile changes were made for this audit.

## Release decisions

| Priority | Decision | Reason |
|---|---|---|
| Block public DNS release | Fix DNS-01, DNS-02 and IO-01. Invalidate the old answer-cache namespace when rolling out. | Cross-client answer integrity and pre-authentication denial of service. Neither requires provider API credentials. |
| Block private/authenticated service | Fix AUTH-01 and AUTH-02; require a passing authentication self-test. | The HMAC signer produced **0 bytes instead of 32** on Node, Deno and Bun. Bearers also escape through provisioning and diagnostic paths. |
| Keep log/analytics **reads** disabled or admin-only | Fix OBS-01 and OBS-02 before enabling them, **including when repairing authentication**. | A DNS credential is not authorization for a log partition; the analytics query is assembled from request strings. |
| Before publishing an image or running a privileged release | Verify TLS mode, move off Node 25, isolate build credentials and scan the artifact **before** promotion. | Missing certs can change the listener type; the shipped Node major is out of support; package locks do not pin everything executed by release jobs. |

Severity is the potential consequence in the deployment described, not an npm rating or a CVSS score. **Critical** here means a breach of the resolver's core trust guarantee for other clients. **High** warrants blocking exposure of the affected path. **Medium** requires more specific configuration, an additional failure, or a narrower impact. Unless a local observation is stated, evidence is from source tracing.

## Resolver and transport

### DNS-01 · Critical on a shared resolver — client packets can enter the answer cache

`src/core/plugin.js:333–360` decodes the incoming DNS message and labels it a question without requiring a standard query, a single question and empty answer/authority sections. On a cache miss reaching the local blocklist decision, the blocked-request branch passes that **incoming packet and its bytes** to the same cache writer used for upstream answers (`src/plugins/dns-op/resolver.js:174–185,225–227,257–268`). `src/plugins/cache-util.js:24–43,98–106` derives freshness from the packet's own response type and TTL, not from its provenance. `src/plugins/dns-op/cache.js:92–105` stores the bytes in the LFU and, where available, the Workers Cache API.

**Impact:** The submitting client gets a block response, but another client sharing that cache and not blocking the entry can receive client-originated DNS data as an answer. The upstream question-matching check is not on this write path. This requires a request admitted by the deployment and a block decision; DNS admission is public when `ACCESS_KEYS` is unset. Scope is the affected shared cache, not global DNS. No live cache was written or read.

**Fix and acceptance:** Reject unsupported input at ingress. Separate *policy metadata* and *validated upstream answer* types and storage APIs; a block decision must never store client bytes as an answer. Change the namespace and purge old entries. Using a recording cache and fake upstream, require that only validated upstream responses can create answer entries in **both** cache tiers, while ordinary blocked requests can still cache policy metadata. Keep the existing two-client filtering tests.

### DNS-02 · High — the DNS decoder can exhaust a process before auth; its encoder can return unwritten bytes

The commit pin in `package.json:36` makes the parser reproducible, not safe for untrusted input. The [pinned decoder](https://github.com/serverless-dns/dns-parser/blob/b7d73b3d7aca64575887758cb75de599fa3e4c01/index.js#L1502-L1514) has a record loop whose termination is not guaranteed by the declared length; the associated [IPv4 reader](https://github.com/serverless-dns/dns-parser/blob/b7d73b3d7aca64575887758cb75de599fa3e4c01/lib/ip.js#L65-L79) does not fail on out-of-bounds indexed reads. The loop can keep appending data without yielding. Name decompression also recurses without a cycle/depth budget, and section arrays are allocated from header counts before checking whether the records can fit (`index.js:77–107,186–189,1926–1938` at the same pin). `src/commons/dnsutil.js:223–229` checks wire size, not expansion or work. This decoder runs synchronously at `src/core/plugin.js:341–353` **before** `userOp` and the request timer. A 4 KiB wire cap, a `try/catch` and an asynchronous timeout do not bound this CPU/heap consumption. On a standalone server it can affect other clients; on managed compute, provider isolation and limits affect the blast radius. No hang or resource-exhaustion test was run.

There is a separate **conditional confidentiality issue** on runtimes with uninitialized native buffer allocation. The [encoder](https://github.com/serverless-dns/dns-parser/blob/b7d73b3d7aca64575887758cb75de599fa3e4c01/index.js#L1900-L1922) returns its whole `allocUnsafe` buffer rather than the written portion. Its name sizer and writer disagree for an ordinary absolute presentation name (`index.js:52–72,112–115`). **Local length-only check:** an ordinary A query encoded to 29 written bytes; the equivalent absolute name returned a 30-byte buffer with **29 bytes written**. The application passes full encoder outputs to callers (`src/commons/dnsutil.js:36–43,232–238`; command lookup at `src/plugins/command-control/cc.js:322–342`). Trailing storage can leave the process; its contents were **not** inspected, and no secret disclosure was established.

**Fix and acceptance:** Upgrade or patch the fork; require bounds, forward progress, record/label budgets and bounded decompression for every decoder. Check the fixed header and supported section counts before invoking a full parser. Size encodings consistently, initialize buffers and return exactly the written range. Gate all runtime bundles on parser conformance and bounded error handling; check byte counts using valid names and supported record types. Header prechecks alone do not protect parsing of upstream answers.

### IO-01 · High — DoH enforces its byte limit only after buffering

`src/server-node.js:1288–1311` collects every body chunk, then concatenates the whole request before checking even the POST limit. This also buffers bodies for methods that do not need one. In the shared handler, POST uses `request.arrayBuffer()`; GET decodes the encoded parameter before checking its decoded length (`src/core/plugin.js:391–399`). `src/core/doh.js:40–55` starts the processing deadline **after** this read and decode. The accepted DNS size is only **17–4096 bytes** (`src/commons/dnsutil.js:14–19,86–92`). Upstream DoH has a fetch timeout but likewise reads the full successful body before validation (`src/plugins/dns-op/resolver.js:289–315`). The outer timeout returns a response; it does not generally cancel the work (`src/commons/util.js:195–229`).

**Impact:** Memory, copies and connection time are consumed before rejecting an unauthenticated request. A large upstream/error response can add memory pressure. Node has socket idle timers and connection controls; neither is a cumulative request byte limit. A managed edge may impose a lower external ceiling, but none was verified. **Fix:** Start an absolute deadline on admission, reject excessive declared lengths early, count actual streamed bytes even without `Content-Length`, cap GET before decoding and cancel on overflow/disconnect. Bound parallel work and apply an edge quota. Test that reading stops at the bound, not just that the eventual status is an error.

**Standalone Deno:** `src/server-deno.ts:132–138,168–210` starts handlers without an application connection budget, allocates from the frame length before applying the DNS limit, assumes one read per field and has no idle deadline. The second read is outside the `try` and the handler promise is not observed. Use bounded exact reads, timeouts, a handler rejection path and `finally` cleanup. This is not the managed Deno Deploy HTTP-only listener.

### DNS-03 · Medium — cached answers lose request semantics and DNSSEC/TTL integrity

The cache key is the revision, normalized name, type and DO indication (`src/plugins/cache-util.js:120–126,169–175`). It omits class, checking-disabled (CD), opcode and upstream/view; a DNS name is concatenated into a URL without a safe component encoding. Neither hit path checks the complete request semantics before rewriting the transaction ID (`src/plugins/dns-op/cache-resolver.js:75–111`; `src/plugins/dns-op/resolver.js:354–366`). The stricter wire key for in-flight coalescing does **not** apply to stored answers. A validating and a checking-disabled client can share an answer that was appropriate only for one.

Cache reads also trim A/AAAA RRsets and can remove signatures without clearing AD. TTL zero can become positive, negative TTLs ignore the SOA, and stale data can be returned with a fresh positive TTL during a grace period (default `CACHE_TTL=1800` seconds). A cached block decision based on an old alias is considered before expiry. See `src/plugins/cache-util.js:24–43,109–116,249–295`, `src/core/env.js:166–170`, `src/plugins/dns-op/cache-resolver.js:85–100`. The upstream race excludes SERVFAIL but not every transient or incomplete result; matching REFUSED/FORMERR or truncated responses can still win, and the normal write gate excludes only SERVFAIL (`src/plugins/dns-op/resolver.js:223–226,305–315`).

**Fix:** Cache only supported standard query semantics; otherwise bypass or reject. Use an unambiguous structured key based on the validated request and resolver view, and verify it on every hit. Preserve full signed RRsets; never advertise authentic data after changing an RRset. Respect authoritative positive and negative TTLs; make serve-stale deliberate, bounded and distinguishable. Define which complete responses can win and which can be cached (retain valid NXDOMAIN). Verify class/CD/DO isolation and signed, negative, zero-TTL and expired answers in both tiers.

### DNS-04 · Medium — a selected filter is not a guarantee that a name is never forwarded

`src/plugins/users/user-op.js:74–109` converts an unparseable flag into a successful request with no usable policy. `src/plugins/dns-op/blocker.js:25–47,56–84` and `src/commons/dnsutil.js:275–285,348–358,381–397` limit blocking to single questions of selected types and gate fresh answer-side alias checking on the first answer. The “already blocked” shortcut treats the presence of **any** sinkhole address as sufficient. A fresh mixed or reordered RRset is not necessarily blocked as a whole. Lookup exceptions also become “not found” (`src/plugins/rethinkdns/filter.js:37–66`). These are distinct from the corrected cold-start wait and per-client cache policy.

**Fix:** Reject malformed explicit policy separately from intentionally absent policy. Specify whether lists govern *all lookups* or only address-resolution types; enforce that contract before forwarding. Inspect all relevant alias records regardless of order. Test the same policy on fresh and cached mixed answers and on unsupported types. Client-selected lists alone are not an administrator-enforced egress policy.

## Credentials, commands and private DNS history

### AUTH-01 · High — access-key HMAC is broken; malformed verifiers can fail open

`src/commons/crypto.js:125–132,150–153` requests a fixed 512-bit HMAC key length when importing arbitrary-length raw material. More importantly, `hmacsign` normalizes the **Promise** from `crypto.subtle.sign`, not its resolved bytes (`:248–251`; `src/commons/bufutil.js:147–179`). `src/plugins/users/auth-token.js:135–175` uses that output for the candidate verifier. `src/core/node/util.js:58–78` also uses it for cross-service certificate-renewal authorization; a correctly verifying peer should reject the request. The peer wasn't audited.

**Observed:** RFC 4231 HMAC-SHA-256 test case 1 passed with native WebCrypto on **Node 22.22.3, Deno 2.5.6 and Bun 1.3.3**. On all three, the application key importer raised `DataError` on the valid vector key. With a correctly imported key, the application signer returned **0 bytes**, expected **32**. These were primitive conformance checks, not authentication attempts.

**Security consequence:** Correctly provisioned nonempty digests do **not** thereby accept everyone: they fail verification, denying legitimate clients. Separately, CSV parsing retains empty members (`src/core/env.js:267–271`), and `src/plugins/users/auth-token.js:84–100` compares a concatenated hostname and digest with `startsWith`, with no syntax or minimum proof-length requirement. A missing digest or empty member can remove the proof requirement if derivation reaches comparison. No keys configured is an intentional public-DNS mode; it must be distinguishable from an invalid configured set.

**Fix and acceptance:** Await signing, enforce a 32-byte result, import variable-length raw material correctly, parse and validate the entire configured set at startup, compare the canonical hostname separately and the full verifier in constant time. Reject malformed configuration rather than enabling public mode. Gate startup/CI on known-answer vectors and test correct, wrong, absent and malformed credentials plus a valid certificate-renewal signature. Reprovision legacy verifiers; don't “fix” failed logins by shortening a verifier or disabling auth.

### AUTH-02 · High where real credentials are used — bearers enter logs, URLs and DoT hostnames

`src/plugins/users/auth-token.js:70–100` logs the submitted bearer and configured verifier set at debug when derivation reaches comparison, and logs mismatch prefixes at warn. Command logging includes the whole URL; Node request-error logging includes it even at warn (`src/plugins/command-control/cc.js:124`; `src/server-node.js:1309,1377–1391`; `src/core/node/util.js:266–272`). The README explicitly sends a fork's reusable secret to an external generator in a GET parameter and places DoT secrets in SNI (`README.md:153–170`). TLS encrypts an HTTPS path in transit but does not hide it from the recipient, reverse proxy or its logs; ordinary SNI is visible without encrypted ClientHello, and hostnames may also be resolved or retained. A verifier is not itself the bearer, but logging the submitted bearer enables replay.

**Exposure is configuration dependent:** Wrangler prod sets `info`, while its default environment uses `debug`; Node defaults to debug and Fly `-dev` forces it (`wrangler.toml:31–34,50–53`; `src/core/env.js:104–108`; `src/core/node/config.js:39–59`). Disabling debug alone does not fix URLs, SNI, error logs or external provisioning.

**Fix:** Provide an offline generator, keep secret material out of all URLs and diagnostics, use an authorization header for capable DoH clients and a revocable transport credential or trusted gateway for private DoT. Do not rely on SNI for secrecy. Make credential and history responses `Cache-Control: private, no-store`; DNS responses currently use public TTL-based caching even on credential-bearing URLs (`src/core/io-state.js:279–286`). Rotate bearers that went through the generator or unredacted logs; restrict access to existing logs/backups and apply retention policy. Test redaction at every log level.

### OBS-01 · High on shared observability deployments — no per-owner authorization for DNS history

`src/core/plugin.js:30–34,379–388` gets the log ID from the request path or, optionally, the hostname. Authentication returns a status, not an identity or authorized partitions (`src/plugins/users/auth-token.js:20–29`). Both read commands check a nonempty ID and successful auth, not whether the reader owns that ID (`src/plugins/command-control/cc.js:260–294`). **No-auth does reject these reads** (`Outcome.no` is true); the broken verifier is not a sound isolation mechanism. If DNS keys are issued to ordinary users, a passing key is given the same read authority as an administrator.

The R2 retrieval path reads the configured bucket/time interval using server credentials and filters the resulting **whole lines** by substring, not the parsed log-ID field. The final unterminated line is emitted without any filter; provider error bodies are passed through (`src/plugins/observability/log-pusher.js:560–612,621–634`; `src/commons/lf-transformer.js:34–56,167–170`). Even a correct caller-ID mapping would not make that stream filter a security boundary. Consequences include exposure of other clients' DNS names, answers and IPs within the returned log scope. Retrieval requires an account ID, API token, configured R2 path/keys, and available data; none were supplied.

**Fix:** Separate DNS access from history-read/admin scopes; derive partitions from an authenticated identity on both writes and reads. Prefer per-tenant objects or provider-side exact selection. If parsing a stream, parse bounded structured records, verify exact ownership for **every** record including EOF, emit only authorized fields, fail closed and cap interval/bytes. Require two-tenant tests with synthetic records, an unterminated final record, permission failures and no provider calls after denial.

### OBS-02 · High with Analytics Engine read credentials — untrusted input becomes SQL

The analytics command passes fields, dataset, interval and limit from URL parameters (`src/plugins/command-control/cc.js:281–294`). `src/plugins/observability/log-pusher.js:515–549` interpolates the dataset, field alias/group, log index and numeric-looking values into SQL and submits it with the server's account token. The column map covers only the projection, not the other insertions; `src/commons/util.js:550–559` bounds via comparisons and returns the original value, not a parsed finite integer. This is a query-construction flaw independent of OBS-01. Potential impact is unauthorized **reads** or expensive queries within the provider dialect, token scope and available datasets, not established write access, OS execution or theft of the token. No provider query was sent.

**Fix:** Select the dataset in server configuration, map each supported field to a complete fixed query fragment, parse strict bounded integers and take the partition only from the authorized principal. Bind values where the API supports it; otherwise use fixed templates and strictly typed/encoded values, never free-form SQL identifiers. Use a dedicated least-privilege read token, short timeouts, quotas and generic error responses. Test rejection before fetch and a snapshot of the query shape for every allowed field.

### OBS-03 · Medium — telemetry collection is not gated by the apparent off switch

`LOGPUSH_ENABLED` defaults false (`src/core/env.js:223–237`) and gates GeoIP setup on disk, **not** execution of the logging plugin. The plugin is registered across runtimes (`src/core/plugin.js:102–125`); for a DNS request with a log ID, an empty source set allows all hosts, and nonempty entries are substring matches. It writes IP, query, answer and filter data via `console.log` before attempting bound analytics; the supplied client-IP header takes precedence over the provider-set header (`src/plugins/observability/log-pusher.js:78–99,160–207,263–279,322–345`). With no ID and no hostname fallback, the plugin skips the record. Without bindings or a provider job, console emission does **not** imply a write to R2 or Analytics Engine. `wrangler.toml:58–75` explicitly enables those integrations for `one`, not all environments. Also, the analytics recorder passes the prefixed query field to a URL-based domain parser (`log-pusher.js:328–335,391–394`); do not assume successful ingestion just because the console line was emitted.

**Fix:** Separate and explicitly gate collection, local logging, analytics export and retrieval. Use exact approved hostnames, bounded structured fields and client addresses only from authenticated ingress. Minimize or truncate IPs, document retention, and test that off means **zero identifying console or analytics events**, even when a request carries a log ID.

## TLS, policy updates and release infrastructure

### TLS-01 · High if backend reachable — missing credentials can select a plaintext listener

With production Node, offload unset and missing certificate configuration, startup selects **cleartext**. It binds HTTP/DNS TCP to the wildcard address on different ports (8055/10555), rather than refusing to start (`src/core/node/config.js:70–111`; `src/server-node.js:418–447`; `src/commons/envutil.js:306–324`). `fly.tls.toml:13–19,43–51,76–84` explicitly terminates TLS at the edge; ordinary `fly.toml:30–41,62–70` points to the other ports, so missing keys there may cause an outage rather than public plaintext. Standalone Deno defaults to repository fixture paths; setting its production stage without an explicit platform can infer managed Deno Deploy and skip local TLS (`src/core/env.js:66–75,325–356`; `src/server-deno.ts:70–115`). The test key is public, not a discovered production secret; Docker excludes `test/`.

**Fix:** Require an explicit, validated TLS mode and platform. Refuse missing/empty certs and fixture identities in production. Restrict cleartext to a trusted private frontend. Replace the deprecated `eval` on operator-controlled `TLS_CN` with an indexed lookup; no request-to-eval path was found. Test a startup matrix, including missing certs, without exposing a listener.

### TLS-02 · Medium, opt-in — PSK enrollment is not private client authentication

The PSK issuance GET returns a long-lived identity/key with no dedicated enrollment scope or `no-store` (`src/plugins/command-control/cc.js:158–176,243–249,476–485`). With PSK enabled and DNS auth unset it is a public enrollment route; with functioning DNS auth, a DNS key suffices. Cached PSK credentials are not invalidated when the in-process derivation seed changes, and enabling PSK disables SNI validation for **all** connections on the DoT listener, not just PSK-authenticated ones (`src/core/psk.js:89–120,129–141`; `src/server-node.js:1052–1073`). This does not reveal the root seed or automatically bypass application DNS auth.

**Fix:** If public PSK is a transport optimization, document that it is **not** client access control. Otherwise require admin/provisioner authorization, separate issuance from public DNS, set expiry/revocation, invalidate cached identities on rotation, and scope SNI relaxation to the negotiated mode. Rotate the seed and restart affected instances if issuance was unintended.

### BL-01 · Medium; requires compromised/corrupt source or disk — runtime blocklists are trusted without authenticating their contents

Build-time metadata pinning, pair validation and atomic rename are good. The MD5 in the fetched config is a **consistency check, not authentication** (`src/build/metadata.mjs:25–44,64–89`). Runtime range downloads are joined without verifying exact `206` ranges, total size or a trusted digest before constructing the trie; local caches are loaded without artifact verification (`src/plugins/rethinkdns/main.js:203–226,346–371`; `src/core/node/blocklists.js:134–159`; `src/core/deno/blocklists.ts:68–94`). Runtime renewal accepts a truthy remote timestamp and tag without the build validator (`main.js:453–465`). The remote timestamp subsequently enters filesystem paths; normalizing a joined path or concatenating it does not enforce containment (`src/core/node/blocklists.js:51–66,176–201`; `src/core/deno/blocklists.ts:33–52,118–135`). This can corrupt filtering, break startup or write the fixed artifact filenames outside the intended subtree within process permissions. Not a DNS-client file-write finding.

**Fix:** Verify a signed or independently pinned SHA-256 manifest for **all** artifacts, including disk reloads; enforce version grammar, monotonicity, sizes, codec and containment. Verify range responses, use bounded fetches and stage the entire generation before swapping it in. On failure keep a verified generation or fail closed. Test interrupted/corrupt updates and preservation of the old generation. The pinned production store at `2026/1794186863982/u6` was not verified in this audit.

### CI-01 · High impact if release tooling is compromised — release jobs execute mutable tools with deployment authority

Fly exports its deploy token at workflow scope, then uses an action from `master` and a `latest` CLI (`.github/workflows/fly.yml:62–66,147–162`). GHCR executes an unverified `latest` SBOM binary with package/attestation/OIDC permissions, and pushes the image *before* scanning (`.github/workflows/ghcr.yml:20–24,46–83,125–129,154–188`). The profiler installs an apt source with `trusted=yes` (`.github/workflows/profiler.yml:113–118`). CF/Deno release jobs also accept a selected ref and execute build code under a deployment job (`.github/workflows/cf.yml:65–69,105–120`; `.github/workflows/deno-deploy.yml:60–69,93–111`). These are trusted push/tag/schedule/dispatch boundaries, **not** evidence that fork PRs receive secrets.

**Fix:** Pin actions to reviewed SHAs, binaries to verified digests, and apt packages to a signed source. Build/test without release credentials; promote an already-scanned digest in an approved environment. Restrict selected refs to reviewed commits, disable persisted checkout credentials where unneeded, and scope deploy credentials to the publishing step/app. Verify action, branch/tag and environment protections in the hosting account.

### IMG-01 · Medium, shipped Node image — the Node image is out of support; build contexts include local files

`node.Dockerfile:1,15` uses floating Node **25** tags in both stages. The [official Node release schedule](https://github.com/nodejs/Release/blob/main/schedule.json) lists end of support as **2026-06-01**, before this audit. The final image installs the native build dependency graph and does not select a non-root runtime user (`node.Dockerfile:24–36`). Base OS packages and effective image user were not inspected in a built image. Separately, `deno.Dockerfile:1–5` copies the entire build context into its final image; `.dockerignore` excludes `.env` and `test/`, but not typical `.env.*`, `.dev.vars` or `.npmrc` local secret files. No such secret was found in the reviewed inputs.

**Fix:** Move to a supported LTS patch, rebuild/test the native addon against the final libc/ABI, pin base digests and run as a dedicated non-root user. Copy an allowlist into final images, isolate writable data directories, exclude local credentials from build contexts, then inspect image contents, UID, SBOM and a vulnerability scan before release.

### Other deployment boundaries


- Node forwards to plain UDP/TCP by default off Fly as well as on its private Fly resolver path. The connected socket constrains the peer and answers are checked against the question, but the incoming client's ID is used upstream and sockets are pooled (`src/core/node/config.js:121–125`; `src/core/node/dns-transport.js:74–87,140–153`; `src/plugins/dns-op/resolver.js:318–351`). Do not promise encrypted DNS beyond the frontend: use authenticated upstreams over untrusted networks; generate independent unpredictable IDs for plain DNS. Handle TCP connect errors **during** connect as well as after it (`dns-transport.js:133–139`); an asynchronous socket error is not caught by a surrounding promise timeout. Ordinary DoH follows redirects and Workers may send an allowed question to **both** configured upstreams; the first reply wins, not exclusive disclosure (`src/commons/envutil.js:164–173`; `resolver.js:278–309`). Restrict configured upstream origins and redirects. No client-selectable arbitrary fetch target was identified on this path.
- Deno's standalone DoT and Node's offloaded TCP listener synthesize a hostname without the client's SNI policy (`src/server-deno.ts:120–137,227–235`; `src/server-node.js:1097–1106`). They cannot supply an SNI-based per-client stamp or bearer. This means missing policy on open deployments or rejection when a bearer is mandatory, **not** a demonstrated auth bypass. Disable those listeners when those features are required unless trusted frontend metadata is carried and verified.
- Production-stage names disagree across adapters: shared Fastly stage detection reads `FASTLY_ENV`, while its template/logger uses `env`; Fly examples set `DENO_ENV` while the Deno stage check uses `DENO_ENV_DOMAIN` (`src/core/env.js:325–331`; `src/core/fastly/config.js:32–40`; `fastly.toml:35–38`; `fly.toml:15–20`). Exception headers containing stacks are suppressed on the basis of that stage (`src/core/io-state.js:98–115,260–267`). Unify production detection, default to redaction, and verify actual response headers/logs, not just log level.
