# Resolver security rollout

**Release hold (18 November 2026).** The code changes address the [review findings](2026-11-18/audit.md); the review is a historical baseline, not evidence about a live service. This tree has no approved production blocklist manifest. Passing two-list fixture tests is not approval to publish an image, install a cloud route or serve customer traffic.

## Blocklist trust input

`scripts/blocklist-version.txt` selects a version, currently `2026/1794186863982`. A timestamp or the store's own MD5 is **not** a trust anchor. Obtain the four hashes and sizes from a separately authenticated producer release, a verified signature, or an independently reproduced, reviewed build. Record that provenance in the change review. Do not download the files and checksum them *from the same untrusted origin* to bootstrap trust.

Check in `config/blocklist-manifest.json` with this schema (described, not sample pins):

| Field | Required value |
|---|---|
| `version` | `YYYY/epochMillis`: 13 decimal digits, UTC year agrees with timestamp |
| `codec` | `u6` |
| `files` | Object keyed by `basicconfig.json`, `filetag.json`, `td.txt`, `rd.txt` |
| `files[name].size` | Positive integer byte count; ≤4 MiB per JSON file, ≤192 MiB per binary |
| `files[name].sha256` | 64 lowercase hex digits; hash the same bytes measured for `size` |

For JSON, bytes are the UTF‑8 encoding of `JSON.stringify(JSON.parse(input))` (producer key order, no extra whitespace or terminal newline); for binaries, exact file bytes. The metadata pair must agree on the filetag checksum and config must match the selected version, u6 and node count. Validate sizes against the target's **actual memory limit**, particularly on edge isolates; the parser caps are not a memory reservation from the provider.

From a clean trusted checkout run `npm install --no-package-lock --ignore-scripts`, then `npm run blocklists:prepare -- --assets`. `BLOCKLIST_BASE_URL` may select a compatible HTTPS mirror. The preparer uses full 200 responses, rejects partial responses, stages binary generations under `blocklists__/YYYY-epochMillis/`, and publishes `src/blocklist-metadata.json` by rename. Interrupted downloads are not published. Do not modify an existing generation in place. Stage as a separate build user; keep the runtime tree, including its ancestors, read-only to the service user. Node/Bun/Deno authenticate files on disk before constructing the in-memory trie; any download fallback must match the **same** pins. No runtime “latest”, range assembly, MD5-only trust or automatic multi-week renewal. Bump both pins in review and rebuild. `BLOCKLIST_VERSION` and `BLOCKLIST_MANIFEST` overrides are for deliberately selected non-release builds, not an escape hatch for missing pins.

## Before enabling traffic

1. **Caches and upstreams.** Purge old Worker/CDN cache entries and any downstream response caches; recycle LFUs by restarting all old instances. The new private answer namespace (`verified-v2`) cannot consume legacy entries. Do not leave a stale worker/version on the same route or fall back to the old namespace. Configure allowed HTTPS resolver origins deliberately. A Worker can race two; disable the secondary if disclosure must be exclusive. Opt into the stamped cold fallback only by agreement with that operator. Keep plain DNS off on untrusted networks. Rate-limit ingress and set body, header, request-time and connection limits at the edge. Local limits are not a global quota. The per-instance answer cache is bounded by both entries (30000) and retained bytes (16 MiB, `src/commons/dnsutil.js`); check peak RSS against the instance size before raising either, because a cached answer can be a full 4 KiB packet.
2. **Private DNS.** Revoke/reissue any legacy URL/SNI credentials, especially bearers sent to another generator or retained by logs. Reissue with `node scripts/access-key.mjs canonical.hostname /secure/private/new-file`. Distribute the bearer out-of-band. Configure only the verifier on the matching host. Restart/redeploy every instance after changing `ACCESS_KEYS`; test correct, absent, wrong-host and retired credentials before reopening ingress. Clients unable to send a header need a separately authenticated gateway, not a token in a DNS name. `/genaccesskey` and `/gentlspsk` no longer vend secrets.
3. **TLS.** Choose the mode below, validate ownership of names/keys, cert expiry, SNI and private backend reachability on the canary. Rotate any previously published PSK or resumption material and drain/restart old listeners. Keep `TLS_ALLOW_ANY_SNI` off. Node session-ticket rotation uses independent random listener keys, not the certificate or PSK; session resumption is not shared across deployments.
4. **Privacy.** Disable legacy provider log jobs, request/tail logging and old R2/analytics bindings **at the provider**, not just in source. Remove old broad API tokens, restrict access to existing logs/backups and apply deletion/retention policy. No historical data is migrated. Configure a new dataset/bucket if collecting new records. Provider access logs and account-level settings are independent of the application switch.

### Listeners

| Configuration | Result |
|---|---|
| Node/Bun `NODE_ENV`/`BUN_ENV=production`; Deno `DENO_ENV_DOMAIN=production`; `CLOUD_PLATFORM=standalone` or `fly`, `TLS_MODE=terminate` | Mount matching PEM `TLS_KEY_PATH`, `TLS_CRT_PATH`. Node/Bun also support a secret `TLS_CERTKEY` containing `KEY=<base64>` and `CRT=<base64>` on separate lines. Production rejects the repository fixture's public key. DoH on 8080; DoT on 10000 only for public DNS. Deno additionally needs a fixed `DOT_POLICY` stamp or explicit `none`; it cannot recover a per-client policy from SNI. `TLS_BIND` may restrict termination to a literal address. |
| Same runtimes, `TLS_MODE=offload` | DoH on 8055, bound to loopback or a literal RFC1918/ULA `OFFLOAD_BIND` (Fly private IP supported). Ensure only the trusted frontend can connect. No plain DNS/TCP listener. Verify the frontend actually routes to that private interface. If the provider requires wildcard plaintext, use termination instead. Node serves cleartext HTTP/1.1 and h2c on that port, selected per connection by the RFC 9113 preface, and refuses a TLS handshake; Bun serves HTTP/1.1 only. |
| Managed Workers | TLS at provider. Verify routes, hostnames and minimum TLS versions there. Workers use `WORKER_ENV`. |

When using private DNS, remove/disable Fly's DoT service and its TCP health check rather than exposing a port on which the app intentionally does not listen. `fly.tls.toml` is an offloaded **DoH-only** example. Optional Node DoT-only TLS 1.2 PSK: `TLS_PSK` is a new random 32–64-byte hex key, identity `sdns-static-v2`. Provision both endpoints privately; do not reuse a bearer, signing key or certificate. No enrollment route, client identity cache, SNI exemption, or private DoT authorization. Stop old instances on rotation. Bun does not implement this PSK callback. Certificate-renewal service signing, where used, needs a separate `KDF_SVC` accepted by the peer; verify the peer before enabling it.

### Optional tenant telemetry (Workers)

- No supplied ID in a path, header or hostname grants access. A two-field `host|verifier` entry is DNS-only. For collection issue a distinct `host|verifier|tenant|write` credential. For reads issue `host|verifier|tenant|read` separately; it cannot resolve DNS. Use lowercase ASCII tenant IDs (alphanumeric first, then alphanumeric, `_`, `-`; max 32). Do not share a bearer between scopes.
- Writes require `LOGPUSH_ENABLED=true`, a `write` principal, an exact source hostname in `LOGPUSH_SRC`, and the sink-specific switch. `LOGPUSH_HISTORY=true` needs an R2 binding `DNS_HISTORY`; `LOGPUSH_ANALYTICS=true` needs Analytics Engine binding `METRICS`. Use a new, access-controlled dataset (`ANALYTICS_DATASET`, default `SDNS_EVENTS_V2`) matching that binding, not the legacy datasets. By default, analytics exports only type and result with the authenticated partition; history also records time. The separate answer-country option below adds a third analytics field, not a history field. No raw DNS names, answers, IPs or request-console sink. Configure a bucket lifecycle rule and a dataset retention policy appropriate to the deployment; limiting reads to the current hour is **not** a deletion policy.
- Reads require `OBSERVABILITY_READS=true`, a `read` principal for the same tenant, and the exact `/logs` or `/analytics` path. History reads check ownership per bounded record, including the final record. Analytics reads additionally need `CF_ACCOUNT_ID` and a dedicated, least-privilege `CF_ANALYTICS_READ_TOKEN`, **not** the deployment token. Supported options: `f=type|result`, `t=1..60` minutes, `l=1..32` rows. No caller-specified dataset, tenant or SQL identifiers. Set per-principal quotas at the gateway and test with two synthetic tenants before enabling. Leave reads off unless necessary.

#### Answer-country breakdown (off by default)

This measures **where the IP in the DNS answer is mapped**, not where the requester or resolver is located. Count at most one country per delivered reply: the first A/AAAA address or self-target HTTPS/SVCB service-mode address hint in Answer order. Gateway rewrites and cache hits use the reply actually served. Blocked, truncated, error and address-less replies have no country. Names, TXT strings and Additional records are not IP sources.

1. Obtain a licensed, independently authenticated **country** dataset. Keep its release, provenance and required attribution with the deployment. Neither a default download URL nor production pins are supplied. To produce the reference files offline from a reviewed DB-IP-style country CSV:
   ```sh
   python3 scripts/geoip-tables.py /data/reviewed-country.csv /data/new-geo-revision
   ```
   Use an uncompressed CSV (≤256 MiB) with no header: `start_ip,end_ip,CC`, inclusive, sorted and non-overlapping per family. The tool writes `dbip.v4` and/or `dbip.v6` in a **new** directory and prints `GEOIP_V4_PIN` / `GEOIP_V6_PIN` for the families present. Each row of the binary is a big-endian range start (4 or 16 bytes) plus two uppercase ASCII country letters, valid up to the next start. Gaps and unassigned ranges use `ZZ`, which is never counted. Compatible existing tables can be used if independently verified. Do not copy fixture labels or pins to production.
2. Publish the exact binary files to a versioned HTTPS directory you control. Set `GEOIP_URL` to that directory (no credentials, query or fragment), and each approved family pin to `<exact byte count>:<lowercase SHA-256 hex>`. Compare pins with the trusted local build, not with values fetched alongside the download. No redirects or partial files are accepted. A warm isolate reuses verified tables (≤16 MiB each); it keeps no per-address GeoIP cache. Test CPU and memory with your actual dataset before enabling it.
3. In addition to the analytics binding, exact host and `write` grant above, set `LOGPUSH_ANSWER_COUNTRY=true`. Only the two-letter code is appended to the event (`blob3`); neither address nor the query name is exported. Lookup is local. A cold isolate can fetch the complete reference file for the address family, **never a URL containing the address**. DNS does not wait for that fetch. A missing/unverified table, an unknown range, or another request already loading a table leaves the ordinary type/result metric intact without a country.
4. With reads enabled, send `GET /analytics?f=country&t=30&l=10` using the tenant's **read** bearer in the `Authorization` header. Example: `[{"category":"IN","n":12}]` means an estimated 12 classified replies (Analytics Engine sampling), not 12 clients or unique IPs. Unclassified and older events are excluded; country totals need not equal all answered queries. Turn `LOGPUSH_ANSWER_COUNTRY` off to stop new enrichment and disable the selector. This does not backfill or erase stored events.

## Release gates

- **Separate merge from deployment.** `workflow_dispatch` controls GitHub Actions, not a provider's Git integration. In particular, Cloudflare Workers Builds can run a dashboard-configured deploy on a push to its production branch; Fly deploys only through the digest-pinned dispatch. Before merging during a release hold, check the Worker's **Settings → Builds → Branch control** and deploy command. Disconnect or pause the production trigger if merging would promote a version. Disabling preview builds alone does not stop production builds. Do not feed fixture pins to a provider build to make its check pass.
- Require read-only PR checks, branch protection on `main`, approval on production environments, app-scoped credentials and a fresh dependency/advisory review. Do not grant secrets to fixture builds or arbitrary refs. Deploy prebuilt Workers; promote containers by digest **after** a successful SBOM, vulnerability scan and provenance check. Do not deploy a mutable tag. Inspect uploaded artifact contents (no keys, `.env*`, dependency trees, profiler outputs or test identities). Rebuild on base-image, compiler or data updates. Never promote a PR fixture artifact.
- Run `npm test`, `npm run lint`, and `npm run audit:dependencies`. No dependency lockfile is committed. Direct package versions and Git commits are pinned; transitive resolutions can change between builds. Audit jobs and image builders generate an npm lock during their own script-disabled install and audit that resolution (full and `--omit=dev --omit=optional`; no allowlist). The Worker release retains its generated resolution only in the short-lived build artifact so its uploader installs the same audited CLI. A standalone audit with no local lock resolves in a temporary directory, not in the source tree. Never treat historical audit counts as evidence about a new install.
- Fastly and managed Deno Deploy are no longer supported targets: their bundles, CI targets, container image and staged release graph have been removed. Deno remains an opt-in **local** runtime; select its fixture target in the manual **PR checks** workflow to type-check it, run the shared conformance suite and exercise a loopback listener. Do not reintroduce an edge-platform deploy path without its own review.
- Build and exercise each actual target. `test/worker-smoke.mjs` uses workerd, the built Worker and an intercepted upstream/store. `test/listener-smoke.mjs node|bun|deno [executable]` runs synthetic traffic on loopback, checks startup rejection and authenticated offload, and pipelines two queries over fragmented DoT framing with a temporary TLS identity (including a Node TLS 1.2 PSK handshake). It requires fixture metadata and built Node/Bun bundles (or a cached Deno source graph), plus `openssl`. `test/conformance.mjs` checks DNS wire and HMAC contracts on Node, Bun and Deno.
- Build each container on linux/amd64, inspect final files and UID, and run with a read-only root, no capabilities, no privilege escalation and no public backend port. Verify startup uses the compiled manifest and local verified data with egress denied. Check memory on **production-sized** lists and TLS health checks under your actual proxy. Review the scan of the exact image being promoted.
- **Not performed here:** independent production pin attestation, Docker builds/OS scans, protected workflow execution, production-sized list test, live-provider canaries, cache purges and credential rotation. No production account was accessed. If any gate fails, stop promotion, disable the affected listener/read path, and retain the last verified generation. Rollback only to a separately verified artifact and compatible access policy, never to a known-unsafe cache/auth namespace.
